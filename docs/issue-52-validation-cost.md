# #52 — 중복 근거 검증 비용 축소

검증 대상 선별, 내용 기반 캐시, 최대 8건의 배치로 반복 API 호출을 줄입니다.

## 동작과 계약

- validation 노드는 현재 `synthesis`의 Assessment/Signal, `tech_analysis`,
  `synthesis_findings`에 연결된 Evidence만 검증합니다. 검색 후보와 과거 근거를
  State에서 삭제하지 않으며, 다음 회차에 참조되면 그때 검증합니다.
- provider마다 메모리에 최대 4,096개의 검증 결과를 LRU로 보관합니다.
  CLI의 새 실행/새 provider에는 새 캐시가 생깁니다. 같은 provider를 재사용하면 캐시도
  재사용되며 디스크나 다른 provider로 공유되지 않습니다.
- 키는 ID·supports_claim·confidence를 제외한 Evidence 내용의 SHA-256입니다.
  주장·발췌·기술·출처가 같고 ID만 다른 경우 같은 검증 결과를 재사용합니다.
  True뿐 아니라 False도 저장합니다. 발췌가 변경되면 이전 True도 다시 검증합니다.
- 모델 객체 교체, 모델명/base URL/reasoning effort, 프롬프트 또는 응답 스키마 변경 시
  캐시를 비웁니다. 같은 모델명 뒤의 서버 내부 버전 변경은 자동 감지할 수 없으므로
  배포 전환 시 provider를 새로 생성해야 합니다.
- 신규 고유 입력만 최대 8건씩 묶습니다. 사용자 JSON은 12,000 UTF-8 bytes 이하로
  제한하고, 초과 시 배치를 나눕니다. 이는 토큰 수가 아니라 보수적인 입력 크기 제한입니다.
  단일 근거 자체가 상한을 넘으면 원문을 자르거나 판정을 꾸미지 않고 ModelOutputError로
  중단합니다. 배치 크기·입력 상한·캐시 상한은 `EvidenceValidator` 생성자에서 조정할 수 있습니다.
- 모델은 `{"results": [{"id": "...", "supports_claim": true}]}`를 반환합니다.
  응답 순서가 달라도 ID로 연결하지만, 누락/중복/알 수 없는 ID/문자열 불리언/추가 필드는
  거부합니다. 단일 판정을 전체 배치에 복사하거나 누락된 결과를 False로 캐시하지 않습니다.
- 잘린 출력/잘못된 응답은 해당 배치만 한 번 재요청합니다. 두 번째도 잘못되면
  ModelOutputError로 중단하며 해당 배치는 캐시하지 않습니다. 앞서 성공한 배치는 재사용합니다.
  TimeoutError/ConnectionError는 기존대로 호출자에게 전달하며 실패를 판정으로 저장하지 않습니다.
- 반환은 입력 순서와 ID를 유지한 Evidence 사본입니다. State를 직접 변경하지 않습니다.
  동일 provider에 동시에 요청이 와도 검증 잠금으로 중복 API 호출을 막습니다.
- 보고서의 근거 지지·기술 일치·보류 규칙, 선택적 재평가, 최대 2회 재검색은 유지합니다.
  demo는 기존대로 외부 호출 없이 실행됩니다. 기존 timeout 상한은 보수적으로 유지합니다.

## 재현 가능한 호출 수 비교

`tests/test_evidence_validation.py`의 합성 fixture와 mock 모델로 측정합니다.
각 회차에 근거 50건이 추가되고 이전 근거는 바뀌지 않으며, 입력 크기 제한에 걸리지 않고
모델 응답 복구가 필요 없는 조건입니다.

| 회차 | 누적 근거 | 이전 개별 검증 호출 | 신규 배치 호출 |
| --- | ---: | ---: | ---: |
| 최초 | 50 | 50 | 7 |
| 재평가 1 | 100 | 100 | 7 |
| 재평가 2 | 150 | 150 | 7 |
| 합계 | | 300 | 21 |
| 동일 입력 추가 호출 | 150 | 150 | 0 |

3회차 합계 호출 수는 **93% 감소**, 모델에 전달하는 근거 항목 수는 300→150으로
**50% 감소**합니다. 미사용 후보를 선별하는 효과는 이 수치에 포함하지 않았습니다.
배치가 커지면 한 호출의 입력/출력 토큰도 커지므로 API 요금이나 전체 실행 시간이
93% 줄었다는 의미는 아닙니다. 실제 모델의 의미 판정 품질 및 전체 real 실행 시간은
이 PR에서 측정하지 않았습니다.

```bash
uv run pytest tests/test_evidence_validation.py tests/test_validation.py -q
make test
make lint
make run
```

실제 실행의 `--verbose` 로그에는 검증 입력 수, 신규 고유 입력 수, 계획된 배치 수가
기록됩니다. 출력 복구 시 추가 호출이 생길 수 있습니다.
